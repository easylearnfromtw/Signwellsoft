# SIGNWELL SOFTWARE 欣緯軟體官網

靜態網站，不需要建置步驟，可以直接放到 GitHub Pages。

## 檔案

| 路徑 | 內容 |
| --- | --- |
| `index.html` | 頁面、樣式與程式都在這個檔案 |
| `assets/three.module.min.js` | three.js r160（MIT License），3D 場景使用 |
| `assets/w/*.webp` | 作品高解析度截圖（五張 2560 × 1600；CMS 保留原檔） |
| `assets/w/preview/*.webp` | 手機 3D 與縮圖專用尺寸，避免常駐完整截圖的解碼記憶體 |
| `.nojekyll` | 讓 GitHub Pages 不經過 Jekyll 處理 |

## 部署到 GitHub Pages

1. 把資料夾裡的所有檔案（含 `.nojekyll`）放到 repo 根目錄，或放進子資料夾。
2. 到 repo 的 Settings → Pages，選擇要發布的 branch 與資料夾。
3. 部署完成後打開網址即可。

## 本機預覽

3D 程式以 ES module 載入，直接雙擊 `index.html` 會被瀏覽器擋下。請在資料夾內開本機伺服器：

```
python3 -m http.server 8000
```

再用瀏覽器開 `http://localhost:8000`。

## 2K 畫質與手機效能

- 16:9 場景為 **2560 × 1440**；手機直向短邊為 **1440 像素**（例如 390 × 844 的畫面，實際繪製 1440 × 3116）。保持長寬比；受 GPU 最大緩衝區尺寸限制時會自動限制。
- 移除原版掉幀時降低解析度的機制。高解析度邊緣取樣取代手機的額外 MSAA；桌面仍使用原生反鋸齒。
- 移除重度景深、動態顆粒與全畫面後處理，改成直接渲染；桌面卡片及手機停穩後的正面卡片使用 1024 像素文字貼圖。手機只保留一張高解析度正面，避免所有卡片同時佔用大量記憶體。
- 手機減少幾何分段，關閉即時陰影，以輕量接觸陰影保留立體感。場景提前準備，文字貼圖分批產生；同一圖片解碼共用。
- 修正每幀新增計時器，減少重複樣式寫入與強制重排；觸控鏡片每幀合併更新；背景分頁暫停動畫。
- 保留原有作品、導覽、對話框、捲動動畫與 WebGL 不可用時的平面版；團隊更新為王曉芬、林哲愷、林哲緯三人，並將服務內容聚焦網站設計與軟體開發。

### 在手機上確認幀率

在網址後加上 `?perf=1`，例如 `http://localhost:8000/?perf=1`。捲入 3D 場景後，角落會顯示**實際渲染尺寸與 rAF 平均幀率**；一般網址不顯示此資訊。此數字不代表螢幕實際呈現的獨立影格數。

**110fps 是優化目標，並非所有手機的保證。** 每幀預算約 9.09ms，需 120Hz 以上螢幕、瀏覽器開放高更新率與足夠 GPU 效能。60Hz 手機最多顯示 60fps；iPhone 的低耗電模式、瀏覽器幀率限制、過熱也可能限制幀率。固定 2K 解析度在低階手機仍有成本，應以實機持續捲動的結果判斷。

桌面開發者工具也可查看 `window.SIGNWELL_PERF`；`cpuMs` 只量測 JavaScript 提交渲染的時間，不是 GPU 完成時間。驗證環境與結果見 `OPTIMIZATION.md`。

## 修改內容

在 `index.html` 裡搜尋以下名稱：

- `const WORKS`：網站作品（名稱、說明、網址、截圖）
- `const PEOPLE`：團隊成員（目前僅王曉芬、林哲愷、林哲緯）
- `const SERVICES`：欣緯軟體六項服務（品牌規劃、網站設計、3D 前端、CMS、數位工具、維護優化）
- `const PARTNERS`：合作夥伴
- `const MODULES`：頁面效果與功能模組
- `const CH=`：企業沿革三章的文字（目前為暫定文字）

## 品牌與版面維護（2026-10-14）

- 官網品牌定位為 **SIGNWELL SOFTWARE／欣緯軟體**，欣緯科技有限公司保留為所屬公司資訊。
- 已移除電子零件、料號及採購等非軟體業務內容，保留既有作品及三階段沿革故事。
